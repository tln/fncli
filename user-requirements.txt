Raw requests captured during development, roughly in order. Not polished

process. [done] marks implemented items.

Initial observations (from gumwagon output)

Detail-row layout
- Put the 26 and '<value>' at top as consts for tuning. [done]
- When the label limit is exceeded: `label` newline, indent + 4, synopsis.
  [done]
- If the synopsis for an option/arg is multiline, indent and put on next

Trimming rules
- When options in a subcommand line are very long, show as [options], then
  always display the options below (not just those with a comment). [done]
- When a synopsis on an arg/command is long, snip it and display a bold
  [...] at the end. Multi-line counts as long. [done]
- Snip the command synopsis at three lines. [done]
- If anything is snipped, display a '--help' option. [done]
- Trimmed output must always advertise --help — including the [options]
  collapse, not just [...] snips. [done]
- Not `command --help` at the bottom: --help should be one of the options
  listed under each command, and only when that command's entry has been
  abbreviated. [done — replaced the bottom pseudo-entry]
- Trim at the edge of the window (terminal width, COLUMNS, fallback 80).
  [done]
- If trimming for lines (lines dropped), put the [...] on the next line
  instead of appending it. [done]
- Correction: an [options] collapse alone is NOT trimming — every option is
  still listed below, nothing hidden, so no --help row for it. Only [...]
  snips advertise --help. [done — supersedes the collapse part above]
- Use 80 chars if the output file is not a tty (measure the stream actually
  written to; $COLUMNS overrides). [done]
- `cmd sub --help` prints everything, so don't list -h/--help there at all.
  [done — --help only appears as a snip advertisement on the terse path]

Streams / conventions
- Fix the stdout issue only: --help to stdout (exit 0), usage errors to
  stderr (exit 2) — the conventional split. [done]

--help behavior
